# 14 维度真的完全无关吗？垂直的关系

> **从最严格的角度**解释"维度正交"和"模型学到的特征"之间的关系。

---

## 1. 短回答

**数学上，768 个维度永远互相垂直**（坐标系是固定的）。

**但模型学到的"概念"经常跨多个维度**，这些维度不一定和别的概念"垂直"。

---

## 2. 严格区分两种"维度"

### 2.1 数学维度（坐标系）

```
768 维空间:
 x₁ ⊥ x₂ ⊥ x₃ ⊥ ... ⊥ x₇₆₈

 永远垂直，永远独立

 这是坐标轴的定义，不随数据变化
```

### 2.2 模型学的"概念维度"

```
模型学到的"性别方向":
  可能是 维度 452 + 358 + 138 + ... 的组合

 模型学到的"水果方向":
  可能是 另一些维度的组合

 这两个"概念方向"不一定互相垂直
```

---

## 3. 数学上的"正交"是什么意思？

### 3.1 2 维例子

```
完美正交的坐标:
 ↑ y
 │     ↑ v₁
 └────→ x

  v₁ 完全在 x 方向
  v₂ 完全在 y 方向
  v₁ · v₂ = 0  ← 点积为 0
```

### 3.2 不是正交的例子

```
非正交的向量:
 ↑ y
 │  ╱v₁
 │╱   v₂
 └────→ x

  v₁ 和 v₂ 都不是纯 x 或纯 y
  v₁ · v₂ ≠ 0
```

### 3.3 数学公式

```
向量 u 和 v 正交（垂直）⇔ u · v = 0
             ⇔ cos(u, v) = 0
             ⇔ 夹角 = 90°

向量 u 和 v 不正交   ⇔ u · v ≠ 0
             ⇔ cos(u, v) ≠ 0
             ⇔ 夹角 ≠ 90°
```

---

## 4. 关键洞察：模型学的"性别"在哪？

### 4.1 假设1：模型在 1 个维度编码"性别"

```
维度 100 = 性别

 man 在维度 100:0.9
 woman 在维度 100: -0.9

 其他维度: man ≈ woman  (无关)
```

这样模型有 767 个维度编码别的，1 个维度专门管性别。

### 4.2 实际（假设2）：模型在多个维度编码"性别"

```
维度 452: man=0.0, woman=0.5
 维度 358: man=0.0, woman=0.5
 维度 138: man=0.3, woman=-0.2
 维度 659: man=0.0, woman=-0.5
 维度 42:   man=-0.3, woman=0.2
 ...

 "性别"是这些维度的某种线性组合
```

### 4.3 我们观察到的是假设2

实际数据（man vs woman）显示**~50 个维度**都有较大差距。

这说明**"性别"不是一个干净的维度**，而是散布在多个维度。

---

## 5. 为什么这样"？

### 5.1 训练目标驱动"性别"分散

```
训练训练时:
  模型要预测"the man ___"后面是什么
  模型要预测"the woman ___"后面是什么

 模型发现:
  - "the man" 后面常跟 "said"（说）
  - "the woman" 后面也常跟 "said"
  - 但说"什么"时，man 和 woman 倾向不同

 模型学到的:
  - "性别"对预测有用
  - 但这个概念分散到很多维度
  - 因为 man/woman 的差异在很多上下文都体现
```

### 5.2 模型没有"性别"这个概念

```
模型不知道"性别"这个抽象概念
模型只知道:
  在某些上下文里，"man" 的某些数字和 "woman" 不同
  这些数字要调整才能预测得更准
```

## 6. 维度 vs特征：三种理解

### 6.1 严格理解（数学）

```
维度 = 数学上的独立坐标
永远正交（坐标系定义）

模型学的"概念" = 维度的某种线性组合

 例:
  "性别" = 0.3 × 维度 452 + 0.5 × 维度 358 + ...
  "水果" = 0.2 × 维度 482 + 0.4 × 维度 537 + ...
```

### 6.2 松散理解（机器学习）

```
不纠结"哪个维度是哪个特征"
直接把 768 维当成"黑盒"

 用法:
  相似的词 → 向量接近
  不同的词 → 向量远离
```

### 6.3 实用理解（程序员）

```
代码里怎么:
  拿到词向量 (768,)
  算余弦相似度
  排序找 top-k

 不需要知道每个维度是啥
```

## 7. 其他证据：维度经常被"借用"

### 7.1 同一个维度编码多个概念

```
维度 452 在 man vs woman 差距大
维度 452 在 apple vs pear 也可能差距大

 如果是这样:
  维度 452 不是"性别"专用的
  它同时编码"性别"和"具体某种水果"

 模型训练时发现:
  "这个维度能区分性别，也能区分水果"
  "  就让它承担两个任务吧"
```

### 7.2 为什么这样高效？

```
如果每个概念占 1 个维度:
  - 768 个概念上限
  - 实际我们需要 10000+ 个概念

如果每个概念跨多个维度:
  - 可以编码 768 × 768 = 60 万个组合
  - 表达力更强
```

## 8. 不同概念的"角度"

### 8.1 几何类比

```
想象一个低维例子（3 维）:

数学坐标轴:
  ↑ z (永久固定)
  │  ╱
  │╱  y
  └─────→ x

模型学的"概念方向":
  "性别方向": [1, 2, 3] (某种组合)
  "水果方向": [4, 5, 6] (另一种组合)
  "动物方向": [7, 8, 9]

这些"概念方向"和坐标轴可能不正交
```

### 8.2 在 768 维中

```
每个概念 = 768 维向量（一个"方向"）
不同概念 = 不同方向

两个概念之间的关系:
 - 正交 = 无关
 - 不正交 = 有重叠

 例:
  "性别" 和 "年龄" 可能不正交（有重叠）
   因为年龄大的男人/年龄大的 经常一起讨论
```

## 9. 主成分分析（PCA）能看出"概念维度"

### 9.1 PCA 的作用

```
拿词向量矩阵 (50000, 768)
↓ PCA
主要方向 (前 50 个)

 这些"主要方向"是:
  - 数据中变化最大的方向
  - 模型学到的"概念方向"
```

### 9.2 实际发现（GPT-2 的研究）

```
研究发现:
  - 第 1 主成分 ≈ "文本相似度"（区分相关 vs 不相关文本）
  - 接下来几个主成分 ≈ "情感"（正/负）
  - 再往后 ≈ "时态"、"主被动"、...
```

每个主成分 = 一个"概念"，但**不是单一维度**，是多个原始维度的组合。

## 10. 实用建议

### 10.1 不要这样想：

```
"维度 452 是性别"
"维度 358 是水果"
```

### 10.2 应该这样想：

```
"模型学的概念分布在多个维度上"
"整个 768 维向量才代表这个词"
```

### 10.3 用相似度而不是分析维度

```
找到相似词的最好方法:
  直接算余弦相似度
  不要去看"哪个维度贡献最大"
```
