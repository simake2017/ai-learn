# test_05_attention：两个词的对话 —— 因果自注意力完整推演

> 本文是 `test/test_05_attention.c` 的配套解释，**所有数字与测试用例一一对应**。
> 测试原文：[test_05_attention.c](test_05_attention.c)
>
> 全文结构：先用图书馆故事讲清 Q/K/V 三个角色（§2），再逐步推演测试数字（§3），
> 然后回答三个"为什么"：为什么 Q·K 不是注意力（§4）、为什么两步代码长不一样（§5）、
> 为什么加权后还要相加（§6）。

## 1. 场景设定：一句话只有两个词

想象模型正在读一句超短的话：

```text
位置 0: "小猫"     ← 一只具体的动物
位置 1: "它"       ← 一个空壳代词，还不知道指谁
```

进入 Attention 层之前，每个词只经历了"查表"（Embedding），所以：

- `"小猫"` 带着猫的特征；
- `"它"` 只是一个通用代词，**自己完全不知道指代的是猫还是狗还是桌子**。

注意力的任务，就是让 `"它"` 回头看 `"小猫"`，把对方的语义借一点过来。

本用例为了手算方便，把规模压到最小：**B=1, T=2, C=4, NH=2**（2 个 head，每个 head 看 2 维），缩放系数 scale = 1/√2 ≈ 0.7071。

## 2. Q/K/V 是什么？—— 图书馆借书版

"它"是个失忆的代词，想写一本《我是谁》的自传，但脑子里空空如也，于是来到图书馆。
图书馆里只有两本书：

| 书 | 内容（V） | 门口贴的索引卡（K） |
|---|---|---|
| 《小猫传》 | [10, 20]（满是猫的萌度和活力） | **[1, 0]** —— 标签写着："动物类" |
| 《代词用法手册》 | [50, 60]（教你怎么当一个好代词） | **[0, 1]** —— 标签写着："语法/事物类" |

而"它"走进图书馆时，心里带着一个问题（**Q = [0, 1]**）：

> "我是个什么性质的词？我该怎么定义自己？"

### 三个角色，对号入座

| 角色 | 图书馆里是什么 | 本质 |
|---|---|---|
| **Q（Query）** | 读者心里的**问题** | "我想找什么"——主动的、有方向的 |
| **K（Key）** | 每本书门口贴的**索引卡** | "我是什么"——被动的招牌，等着被比对 |
| **V（Value）** | 书架上书的**实际内容** | "我有什么"——真正会被取走的东西 |

注意：每个词同时扮演三个角色。"小猫"在给别人当标签（K）和货物（V）的同时，自己也有提问（Q）。

### 关键设计：为什么 K 和 V 要分开

如果索引卡就是书本身，检索会变成"把每本书从头翻到尾才知道它讲什么"——成本高且"类别"和"内容"混淆。K/V 分离：

| | 职责 | 要求 |
|---|---|---|
| K | 只做**匹配** | 越精炼越好，一个标签就够 |
| V | 只做**被取走** | 越丰富越好，是全部干货 |

**招牌（K）决定借不借，内容（V）决定抄多少。**

## 3. 逐步推演（head0，数字与测试一致）

### Step 1：拿问题对索引卡（Q · K / √d）

```text
对《小猫传》的索引卡 [1, 0]:
    Q·K = [0,1]·[1,0] = 0×1 + 1×0 = 0     → "动物类"答不了"我是什么词"
对《代词手册》的索引卡 [0, 1]:
    Q·K = [0,1]·[0,1] = 0×0 + 1×1 = 1     → 完美命中！×0.7071 = 0.7071
```

得到的是**匹配度初评**，还不是注意力（详见 §4）。

### Step 2：因果掩码 —— 不许偷看未来

`"小猫"`（位置 0）在位置 1 之前，它**只能看自己**：

```text
score[0][0] = [1,0]·[1,0] × 0.7071 = 0.7071
score[0][1] = -∞  （因果掩码：未来位置直接屏蔽）
att[0] = softmax([0.7071, -∞]) = [1.0, 0.0]
```

这就是因果掩码的意义：训练时整段话一次喂进去，位置 t 的答案绝不允许
偷看 t 之后的词，否则就是在"抄答案"。

### Step 3：softmax —— 初评意见变成借阅比例

```text
初评分数:  [0,     0.7071]     ← 随便什么实数都行
              ↓ softmax
借阅比例:  [0.3303, 0.6697]   ← 必须 ≥0 且加起来 = 1

e^0 = 1.000,  e^0.7071 ≈ 2.028,  求和 = 3.028
att[1] = [1/3.028, 2.028/3.028] = [0.3303, 0.6697]
```

含义非常直白：**《小猫传》借 33%，《代词手册》借 67%**。

### Step 4：按比例取内容，倒进同一个桶（×V 求和）

head0 中 V[小猫] = [10, 20]，V[它] = [50, 60]：

```text
从《小猫传》抄:  0.3303 × [10, 20] = [3.3,  6.6]    ┐
                                                    ├→ 相加
从《手册》抄:    0.6697 × [50, 60] = [33.5, 40.2]  ┘
─────────────────────────────────
自传第一章 out[1] = [36.788, 46.788]
```

而 `"小猫"`（位置 0）因为只能看自己，输出原封不动就是自己的 V：

```text
out[0]_h0 = 1.0 × [10, 20] = [10, 20]
```

**为什么必须"倒在一个桶里"、而不是让两本书并排呆着？** 因为"它"最终只能有
**一个向量**——下游 MLP、下一层 Attention 都期望"每个 token 一个向量"（详见 §6）。

## 4. 为什么 Q·K 不是注意力？—— 初评意见 ≠ 借阅比例

### Q·K 之后得到的是：原始匹配分（score）

代码里它叫 `preatt`（attention.c 第 51 行）——前缀 pre 就是"还没成 attention"。
它此刻的身份是：**图书馆管理员的初评意见**。

### 它是"匹配度"，但不是"是否命中"的布尔开关

点积度量两个向量**方向有多一致**，是连续的分级：

| 点积结果 | 几何含义 | 图书馆版 |
|---|---|---|
| 大的正数 | 两向量指向几乎相同 | "这本书完全能回答我的问题" |
| 0 | 两向量**正交**（垂直） | "这本书的类别和我的问题不搭边" |
| 负数 | 两向量指向相反 | "这本书讲的正好和我的问题对着干" |

测试里的两个值正好踩在两头上：`0` = 完全正交（动物类答不了"我是什么词"），
`0.7071` = 同方向命中。注意 0 的意思是"无关"，不是"命中失败"。

### 从匹配分到注意力，softmax 干了三件事

1. **exp 把分数变正**：原始分可以是负数，比例不能是负的
2. **归一化加起来等于 1**：这才使"加权混合"合法（§6 的配方单）
3. **放大差距**：原始分差只有 0.707，比例却被拉大到 33/67——softmax 天生偏爱高分者

### 那 0.7071 是哪来的

scale = 1/√d。原因：维度越多，点积天然越大（各项相加），d 大时分数可能冲到几十，
softmax 一 exp 就数值爆炸。除 √d 把分数按维度规模归位，让 softmax 工作在正常区间。

## 5. 为什么 Step 1 和 Step 4 的代码长不一样？

看 attention.c 的两个循环，嵌套顺序正好相反：

```c
// Step 1（L40~53）：算分数
for (int t2 = 0; t2 <= t; t2++) {     // 外层：遍历"看哪个词"
    float val = 0.0f;
    for (int i = 0; i < hs; i++)      // 内层：把维度压成一个数
        val += query_t[i] * key_t2[i];
    preatt_bth[t2] = val;             // 每个 t2 得到一个标量
}

// Step 4（L76~84）：加权求和
for (int i = 0; i < hs; i++) {        // 外层：遍历"输出向量的每个维度"
    float o = 0.0f;
    for (int t2 = 0; t2 <= t; t2++)   // 内层：把所有词压成一个数
        o += att_bth[t2] * value_t2[i];
    out[...] = o;                     // 每个维度 i 得到一个标量
}
```

这不是"计算不一样"，而是**两步在约减不同的轴**：

| 步骤 | 公式 | 输入 → 输出 | 被约减的轴 | 循环顺序 |
|---|---|---|---|---|
| Step 1 | score[t2] = Σ_i Q[i] × K[t2][i] | 向量 · 向量 → **一排标量** | 维度 i | t2 外，i 内 |
| Step 4 | out[i] = Σ_t2 att[t2] × V[t2][i] | 标量 × 向量 → **一个向量** | 词位置 t2 | i 外，t2 内 |

更根本的原因：**两步回答两个性质不同的问题**——

- **Step 1 是判断**："我和每个词有多相关？" 判断的结果天然是标量，一锤定音，
  且要对每个候选词各问一次 → 结果按"看的是谁"（t2）索引。
- **Step 4 是搬运**："我该把哪些内容搬进我的新表示？" 内容是向量，不能压；
  而搬运的比例对所有维度共享 → 每个维度各做一次加权平均，按"哪个维度"（i）索引。

生活版类比：走访 3 家装修公司每家打个分（一排分数，按"哪家"索引）→
按分数比例从各家搬家具（一整套家具，按"哪个房间"索引）。
打分环节留下的是分数单，搬家环节留下的是每个房间的东西。

两个循环合起来看，就是两个矩阵乘法夹一个 softmax：

```text
Step 1:  score = Q · K^T    (T×hs)·(hs×T) → T×T    约减 hs
Step 4:  out   = att · V    (T×T)·(T×hs)  → T×hs   约减 T
```

矩阵乘法在 C 里就是三层循环，哪个轴被压掉，它就出现在最内层。

## 6. 为什么注意力 × V 之后还要相加？—— 调色故事

这是注意力**全部深刻性所在**。

### 场景："它"拿着配方单来到调色店

| 色料 | 向量 | 维度含义 |
|---|---|---|
| 小猫色 | [10, 20] | 维度0=萌度， 维度1=活跃度 |
| 自己色 | [50, 60] | 它作为代词的底子 |

配方单（att）：**33% 小猫色 + 67% 自己色**

### 第一步：按配方取料（att × V）

```text
小猫色舀出:  0.3303 × [10, 20] = [3.3, 6.6]    ← 一小勺，浅浅的猫味
自己色舀出:  0.6697 × [50, 60] = [33.5, 40.2]  ← 一大勺，自己的底色
```

乘法把每个来源词的内容**裁出对应份额的一份**。现在桌上有两杯料。

### 第二步：倒进同一个桶（相加）

关键问题：**为什么要把两杯倒在一起？**

因为"它"最终要的是**一个颜色**——画布上的一个像素只能显示一种颜色，
不可能左半边猫色右半边己色（那样下游看到的是"裂成两半的词"，模型契约崩了）。
两杯料必须合并成一个：

```text
        [3.3, 6.6]   ← 小猫那杯倒进去
      + [33.5, 40.2] ← 自己那杯倒进去
      ─────────────
  out = [36.8, 46.8] ← "它"的身份色出炉
```

### 混合色在几何上是什么：插值

| 颜色 | 萌度 | 活跃度 | 观感 |
|---|---|---|---|
| 纯小猫色 | 10 | 20 | 浅浅的 |
| **混合色（out）** | **36.8** | **46.8** | **比小猫深，比自己浅** |
| 纯自己色 | 50 | 60 | 深深的 |

因为注意力权重和为 1，这个和是**凸组合**——结果永远落在两个 V 端点连线的内部：

- att 全给小猫 (1, 0) → 结果爬到小猫端点 [10, 20]
- att 全给自己 (0, 1) → 结果爬到 [50, 60]
- 33/67 → 落在连线上离自己 1/3 处

**"借语义"的几何本质：在语义空间里，从"自己"出发，沿着通往"小猫"的连线走 33% 的路程。**

### 为什么偏偏是"加"，不是别的合并方式

1. **语义可加**："像猫又像自己"本来就是两种成分的叠加
2. **线性保梯度**：相加可微，误差能传回 Q/K 的打分，匹配过程才得以被训练
3. **替代方案都不行**：
   - 只取最大（硬注意力）：表达不了 0.33/0.67 这种"半像半不像"的细腻情况
   - 拼接向量：输出维度翻倍，破坏"每 token 一个定长向量"的契约

### 一句话收拢三个角色

```text
乘：把每个词的内容按配额裁剪
加：把裁剪后的份额在同一语义空间里叠成一个点（插值）
```

## 8. head1 在哪？

head1 使用维度 2、3，输入为：

```text
Q/K: [1,0] / [0,1]（与 head0 相同）
V:   [30, 40] / [70, 80]  （恰好是 head0 的 V + 20）
```

计算过程与 head0 一模一样，结果：

```text
out[0]_h1 = [30, 40]
out[1]_h1 = [0.3303×30 + 0.6697×70, 0.3303×40 + 0.6697×80]
          = [56.788, 66.788]
```

完整输出（测试里的 out[0..7]）：

```text
out = [10, 20, 30, 40,  36.788, 46.788, 56.788, 66.788]
       └── t=0 ──┘        └─────── t=1 ────────┘
```

两个 head 用同一套匹配规则、各自处理不同维度的 V——这就是"多头"的本质：
**同一句话，多个视角同时各看各的**。

## 9. 全流程串讲：四个阶段各是什么

```text
Q·K/√d  →  匹配度初评     （preatt：任意实数，"谁和我相关"）
  ↓ softmax + 归一化
attention  →  借阅比例     （att：0~1，总和=1，才能当调色配方）
  ↓ ×V
按配额取料  →  各份额向量   （att[t2]×V[t2]：裁出"流进我的一份"）
  ↓ 求和
out        →  插值出新表示 （凸组合：在语义空间连线上走 att% 的路程）
```

三幕剧的分工：

| 数学 | 图书馆版 | 调色店版 |
|---|---|---|
| Q·K 打分 | 拿问题对索引卡 | 品鉴哪桶料适合 |
| softmax | 评分换算成借阅比例 | 配方单：33% / 67% |
| att × V 求和 | 按比例取书、合成笔记 | 取料、倒进一个桶 |

打分、softmax 全是准备——只是在算"该按什么比例混"；
唯有 ×V 求和真正动手混了。**比例再精妙，不倒进桶里，"它"就永远只是一张配方单。**
